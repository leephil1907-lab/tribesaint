# Tribe Culture — storefront

A production multi-page streetwear store for **Tribe Culture (established MMXXVI)**: a Three.js product showcase on the homepage, live stock, server-authoritative Paystack checkout, order emails, order tracking and a full operations dashboard.

Dependency-free front end (HTML/CSS/vanilla JS + a locally vendored Three.js) and a zero-dependency Node server that also runs on shared cPanel hosting.

## Admin dashboard

### How the console is kept off the storefront

* The console lives in `private/` — outside the public HTML root — and `/private/*` returns 403 from the static handler.
* There is no `admin.html` in the site. `/admin.html` returns **403**, and no nav, footer, sitemap or robots entry points at the console.
* `/studio` redirects to `/studio/signin` unless the request carries a valid session cookie. `/studio/signin` is the only public-facing studio file and contains nothing but the password field.
* Signing in sets `tc_studio` — `HttpOnly`, `SameSite=Strict`, 12-hour expiry, `Secure` under HTTPS. No token is ever written to `sessionStorage` or exposed to page scripts.
* `/studio/logout` clears the cookie and returns to the sign-in screen. Every `/api/admin` action accepts the cookie *or* a `Bearer` token, so scripted/CI access still works.
* The password comes from `ADMIN_PASSWORD`. On boot the server prints a warning while the default `change-me-tribe-2026` is still in use, and the dashboard shows a banner until it is replaced.

The **Invoices** view is the document desk: pick an order and a document type (invoice or receipt), preview it in the branded layout, then open, print, download as PDF, email it to the customer or send it on WhatsApp. Numbers are sequential — `TC/INV/2026/0001` and `TC/RCT/2026/0001` share one counter — and each document is issued once, with the issue time logged in the table underneath. The same document is attached as a PDF to the order email and linked from the thank-you page and the customer's tracking view. PDFs are generated by `invoice.js` (a dependency-free A4 writer) and carry the crest, the wordmark and the site's bone-and-red styling.

* **Overview** — orders, paid, pending, revenue, items sold, list size, unread messages, Paystack mode warning, latest orders, stock snapshot.
* **Orders** — search, filter by status, expandable detail (items, address, history, amount-mismatch warning), status transitions `paid → packed → shipped → delivered` (plus `cancelled`/`refunded`), CSV export.
* **Products & stock** — live price, live/hidden toggle, per-size stock grid (0 hides the size and disables add-to-bag).
* **Customers** — newsletter list and derived buyers (orders + spend), CSV export.
* **Messages** — contact-form inbox, reply links, read/unread.
* **Settings** — store email, free-delivery threshold, NG/INTL rates and ETAs, Paystack mode, webhook URL.

## Run locally

```bash
node server.js                 # http://localhost:3000  (PORT / HOST supported)
PORT=3000 TC_DATA_DIR=/tmp/tcdata node server.js
```

No `npm install` is required — there are no runtime dependencies.

Node 18+ is all that is needed. (`vercel.json` is included for the Vercel connector, but Vercel's filesystem is read-only in practice: use Render with a disk if you want orders and stock to persist.)

## Deploy to Render

`render.yaml` is a ready blueprint (Web Service, Node runtime, health check `/api/health`, 1 GB disk mounted at `/data`).

1. Push this folder to a Git repository and choose **New → Blueprint** on Render, or point a Web Service at it:
   * Build: `npm install --omit=dev`
   * Start: `node server.js`
   * Health check: `/api/health`
2. Add a **Disk** mounted at `/data` and set `TC_DATA_DIR=/data`.
3. Set the environment variables:

| Variable | Notes |
| --- | --- |
| `SITE_URL` | `https://your-domain` — used for callbacks, emails and the webhook URL |
| `ADMIN_PASSWORD` | Strong password for `/studio` |
| `STORE_EMAIL` | Where new-order and message alerts go |
| `FROM_EMAIL` | Verified sender for Resend |
| `PAYSTACK_PUBLIC_KEY` / `PAYSTACK_SECRET_KEY` | Start with `pk_test_`/`sk_test_`; switch to `sk_live_` only after a real test order and email delivery both succeed |
| `RESEND_API_KEY` | Optional — without it, mail is written to `data/mail.log` instead |
| `ALLOW_PREVIEW_CHECKOUT` | `true` lets orders be placed with no Paystack keys (test mode, no money) |

4. In Paystack → Settings → API Keys & Webhooks, set the webhook URL to `https://your-domain/api/webhook`.

`api/data/store.json` is created automatically on first write. On Render the filesystem is ephemeral, so always mount the disk — otherwise stock, orders and messages reset on deploy.

## Money and trust model

* Prices, shipping and stock are recomputed **server-side** in `POST /api/init`; the browser cannot alter them (a tampered `price: 1` still costs the real amount).
* An order is `paid` only when Paystack's `/transaction/verify/:ref` returns `status === 'success'` **and** the amount and currency match the order — otherwise `mismatch`.
* Stock decrement, counter updates and emails happen once, guarded by `paid_at` / `stock_deducted` / `email_sent`.
* `POST /api/webhook` requires a valid `x-paystack-signature` (HMAC-SHA512 of the raw body) and is idempotent with the verify path.
* Rate limits (per IP, in memory): init 12/10 min, signup 8/10 min, contact 5/10 min, track 30/5 min, verify 40/5 min, admin login 8/15 min.

## API

| Endpoint | Notes |
| --- | --- |
| `GET /api/health` | `{ ok, uptime, mode }` |
| `GET /api/catalogue` | Brand, currency, shipping, products with prices and per-size stock |
| `POST /api/init` | `{ items:[{sku,size,qty}], customer }` → reference, total, Paystack authorization |
| `GET /api/verify?reference=` | Re-checks with Paystack, returns the public order |
| `POST /api/webhook` | Paystack charge events |
| `POST /api/signup`, `POST /api/contact` | List signup, contact message |
| `GET /api/track?reference=&email=` | Guest order status |
| `GET /api/invoice?reference=&type=invoice\|receipt&token=…&format=json\|pdf` | Branded invoice / receipt (token from the order, or an admin Bearer session) |
| `GET/POST /api/admin` | `login`, `overview`, `order-status`, `stock`, `product`, `settings`, `message-read`, `invoice-send` (Bearer token) |

`server.js` is the single source of truth for these endpoints — nothing is computed in the browser.

## Theme

Every page ships an ink (default) and a bone/daylight theme. The switch lives in the top bar on every page and inside the mobile menu; the choice is stored in `localStorage` (`tc-theme`), applied before first paint by a tiny inline script, and announced to the OS through `meta[name=theme-color]`. All surfaces flow through CSS custom properties (`--ink*`, `--field`, `--topbar`, `--wash*`, `--on-accent`), so a theme is one token block — the 3D stage stays ink in both themes because it is a display surface.

## Motion

* **Cross-document view transitions** (`@view-transition`, `view-transition-name` on the header and footer) where the browser supports them; elsewhere a 240 ms curtain wipe on internal navigation.
* **Section reveals** through one `IntersectionObserver` in `store.js`, with a `MutationObserver` catching product grids, related pieces and studio rows that are rendered later.
* The homepage adds a **live 3D showcase** (`#live`): a real turntable on the drop, a piece picker (drop-down), twelve chips, face switching, an auto-advance that stops the moment a visitor touches the stage, and a "Surprise me" shuffle.
* The **drop poster** (`#drop`) hangs four pieces on a rail — hooks, shadows, tilt-in animation, all links live.
* Everything above is disabled under `prefers-reduced-motion: reduce`.

## Selection inputs

Category, family and sort on the shop, and size on the product page, are drop-downs (`select` elements with a custom caret), not chip rows. They are URL-driven — `shop.html?category=tees&family=saint&sort=low` — so a filtered view can be shared, and the category counts are recomputed from live stock.

## Link previews and app icons

* `manifest.webmanifest` with 192/256/384/512 icons plus maskable variants, app shortcuts (Shop, Track, World) and `standalone` display.
* `assets/icons/*`, `assets/apple-touch-icon.png`, `assets/favicon.ico` and per-size PNG favicons, all generated from the brand crest.
* Every page carries `og:*` and `twitter:*` with an absolute 1200×630 image, `max-image-preview:large`, canonical URL and a locale.
* `product.html?sku=…` is rewritten server-side so the shared link previews **the actual piece** — its name, variant, price, blurb and photo.

## Assets and performance

* No CDN dependencies: Three.js r160 is vendored at `assets/vendor/three.module.min.js`, fonts are self-hosted in `assets/fonts/` (Anton, Oswald variable, Pinyon Script) and preloaded.
* The 3D stage is a module loaded after first paint, pauses when off-screen or the tab is hidden, and falls back to a product image when WebGL is unavailable (`data-stage-ready="fallback"`).
* Static assets are served immutable with gzip; MP4 range requests are supported for the drop film.
* All motion respects `prefers-reduced-motion`.
* The PDP turntable mounts each face as a framed plate using the pre-vignetted art in `assets/products/3d/` (`<sku>-front|back|detail.jpg`), so the photography sits on the black stage instead of punching a bright rectangle into it.
* Live chat is WhatsApp: the floating button, the PDP link and the contact-page block all open `wa.me/2347064844525` with a pre-filled message. Change `support_phone` in `config.json` to move it.

## Content to update before going live

* `config.json` — prices, sizes, `default_stock`, shipping rates, `free_delivery_over`, `support_phone`.
* `config.json` → `invoice` — `terms`, `notes`, and the bank block (`name`, `bank`, `account`). Bank fields are **intentionally blank** until you supply the real account; while they are blank the document prints "Bank transfer details are confirmed on request" instead of inventing a number.
* Photography in `assets/` (the product `images.front|back|detail` paths in `config.json`).
* `SITE_BASE` in the page head (canonical/OG URLs) if the domain differs from `tribeculture.store`.
